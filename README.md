# Чудик

[![CI](https://github.com/dimaaan/chudik-chat/actions/workflows/ci.yml/badge.svg)](https://github.com/dimaaan/chudik-chat/actions/workflows/ci.yml)

P2P-чат для домашней сети. Без сервера, без регистрации, без истории.

Открыли на двух устройствах в одной wifi — увидели друг друга, переписываетесь,
перетаскиваете файлы и папки. Закрыли — ничего не осталось: ни переписки,
ни списка контактов.

## Как запустить

```bash
# Windows (неупакованная сборка)
dotnet run --project src/ChudikChat.App -f net10.0-windows10.0.19041.0

# Android (нужно физическое устройство в той же wifi, эмулятор не подойдёт)
dotnet build src/ChudikChat.App -f net10.0-android -t:Run

# macOS — только на самом Mac
dotnet build src/ChudikChat.App -f net10.0-maccatalyst

# Тесты
dotnet test tests/ChudikChat.Core.Tests/ChudikChat.Core.Tests.csproj

# То же, что гоняет CI: без трёх тестов, которым нужны multicast и UDP 45678.
# Локально их прогонять обязательно — автоматика обнаружение не покрывает.
dotnet test tests/ChudikChat.Core.Tests/ChudikChat.Core.Tests.csproj --filter "Category!=Multicast"

# Консольный стенд: два таких в разных окнах — основной способ отлаживать протокол
dotnet run --project src/ChudikChat.Cli -- Алиса
```

## Готовые сборки

**Скачать можно со [страницы релизов](https://github.com/dimaaan/chudik-chat/releases)** —
MSI, APK и DMG собираются автоматически на каждый коммит в `main`. Собирать
самому нужно, только если правишь код.

### Windows, x64

```powershell
# подготовка WiX — один раз на машину
dotnet tool install --global wix
wix eula accept wix7
wix extension add -g WixToolset.Firewall.wixext

# сборка
./build/publish-windows.ps1
```

На выходе `artifacts/Chudik-2.0.0-x64.msi` — один файл, который можно унести
на другую машину. Внутри всё нужное, включая рантайм .NET и Windows App SDK:
на той машине не понадобятся ни SDK, ни воркло́ды MAUI.

Ставится для всех пользователей (нужны права администратора) и заводит два
правила брандмауэра — **на программу, а не на порт**. Это не придирка: TCP-порт
слушателя эфемерный, он выбирается при старте, и правило на конкретный номер
не сработало бы никогда.

Три вещи, о которых лучше знать заранее:

- **MSI не подписан.** Windows покажет «Windows защитила ваш компьютер» —
  нужно «Подробнее» → «Выполнить в любом случае».
- **Только x64.** На ARM64-машине не запустится.
- **Удаление не трогает принятые файлы** в `%USERPROFILE%\Downloads\ChudikChat`:
  они принадлежат пользователю, а не установщику.

Ни AOT, ни single file не используются. Windows App SDK их поддерживает,
и MAUI не запрещает, но и ничего про них не обещает: риск ложится ровно
на перетаскивание файлов и выбор папки, где проекции WinRT строятся в рантайме.
Такая поломка не видна при сборке — она ждёт первого перетаскивания.

### Android, arm64

```powershell
./build/publish-android.ps1
```

Нужны воркло́д `android`, JDK от 17 до 21 и Android SDK с платформой android-36:
всё это приносит Visual Studio с нагрузкой .NET MAUI. На выходе
`artifacts/Chudik-2.0.0-arm64.apk`.

Тоже три вещи, о которых лучше знать заранее:

- **Обновление поверх предыдущей версии не встанет.** Постоянного ключа подписи
  у проекта нет, а отладочный .NET Android генерирует заново — свой на каждой
  машине и на каждый запуск CI. Android видит другую подпись и считает пакет
  чужим приложением. Придётся удалить старую версию, **а вместе с ней пропадёт
  всё принятое**: на Android оно лежит в папке приложения. Лечится постоянным
  ключом — четыре секрета в репозитории и `AndroidKeyStore=true` в сборке.
- **Только arm64.** На 32-битном устройстве не установится. x86_64 из умолчания
  SDK отключён сознательно: он нужен эмулятору, а в эмуляторе Чудик всё равно
  никого не находит.
- **Минимум Android 8.** Ниже нет каналов уведомлений, без которых не живёт
  служба переднего плана.

### macOS, Apple Silicon

```powershell
./build/publish-maccatalyst.ps1
```

Только на самом Mac — нужен Xcode, причём той версии, которую просит воркло́д
(`_RecommendedXcodeVersion`, сейчас 26.6). При расхождении major.minor сборка
падает с E0191: это ошибка, а не предупреждение. На выходе
`artifacts/Chudik-2.0.0-arm64.dmg` — образ с бандлом и ссылкой на «Программы».

Размер образа задаётся явно, а не вычисляется `hdiutil` по содержимому:
на первом же прогоне в CI автоматический расчёт промахнулся и создание упало
с «No space left on device» — место кончилось не на машине, а внутри самого
образа. Подробности в комментарии в `build/publish-maccatalyst.ps1`.

И снова три вещи:

- **Подпись ad-hoc, без нотаризации.** На Apple Silicon подпись обязательна —
  неподписанный код там просто не запускается, — но доверия ad-hoc не даёт.
  При первом открытии macOS скажет, что не может проверить разработчика;
  разрешается один раз через Системные настройки → «Конфиденциальность
  и безопасность» → «Всё равно открыть». Control-клик по значку, которым это
  обходили раньше, в macOS 15 уже не помогает.
- **Только Apple Silicon.** Умолчание SDK — универсальная сборка вместе с Intel;
  она отключена, это лишние мегабайты ради машин, которых нет.
- **`Platforms/MacCatalyst/Entitlements.plist` применяется, и приложение живёт
  в песочнице.** Здесь долго было написано обратное — будто автоподхват ищет файл
  в корне проекта и потому мимо него. Это неправда: файл подхватывается из папки
  платформы сам, без единой строчки в csproj, и все четыре его ключа доезжают
  до подписи и в Debug, и в Release. Смотреть так:
  `codesign -d --entitlements - <бандл>`. Песочница при этом настоящая — система
  заводит контейнер `~/Library/Containers/com.chudik.chat`. В Release сборка
  добавляет к этим четырём ещё `com.apple.security.cs.allow-jit`: без него среда
  исполнения .NET не стартует вовсе.

  Чем это оборачивается для принятых файлов — **не проверено**. В песочнице путь
  к «Загрузкам» ведёт внутрь контейнера; ровно поэтому `DownloadRoot` на macOS
  обходит контейнер через `getpwuid`, но пропустит ли песочница саму запись
  наружу, никто не смотрел. Это первое, что стоит проверить на образе.

## Что внутри

```
src/ChudikChat.Core     ядро: обнаружение, транспорт, передачи. Без зависимости от MAUI
src/ChudikChat.Cli      консольный хост движка — стенд для отладки
src/ChudikChat.App      приложение MAUI: Windows, Android, Mac Catalyst
tests/                  протокол, санация путей, передачи по loopback
```

Жёсткое правило: **`ChudikChat.Core` не ссылается на MAUI.** Поэтому протокол
гоняется в тестах и в консоли, а не только на двух устройствах.

## Как это работает

**Пир — это GUID, сгенерированный при старте процесса.** Не IP, не имя, не MAC.
Отсюда всё остальное: смена адреса не создаёт нового собеседника, машина с wifi,
ethernet и VPN не двоится в списке, а два экземпляра на одной машине — два
законных пира, на чём и держится весь цикл разработки.

**Обнаружение** — UDP на порту 45678: приём на сокете, привязанном к `0.0.0.0`
и вступившем в группу `239.255.42.99` по каждому пригодному интерфейсу; отправка
со второго сокета на эфемерном порту, в многоадресную группу и в направленный
broadcast каждой подсети. `HELLO` при старте, объявление каждые ~4 с, прощание при
выходе; молчание дольше 15 с означает уход.

Адрес пира берётся из заголовка датаграммы, из полезной нагрузки — только TCP-порт.
Отправитель не знает, какой из его адресов виден получателю, а самопровозглашённый
адрес позволял бы перенаправлять чужие соединения.

**Транспорт** — короткое TCP-соединение на каждое взаимодействие, постоянных сессий
нет. Текст: `Identify → Identify → Text → Ack`. Передача: то же представление,
затем `Offer → Decision → записи → End → Ack`. Никаких встречных коннектов,
переподключений и keepalive, а передача папки на четыре гигабайта не мешает переписке,
потому что идёт по своему соединению.

**Картинка учётной записи** едет по сети отпечатком, а байты — по запросу.
В объявлении и в представлении идут 32 символа хеша; увидев незнакомый отпечаток,
движок отдельным коротким соединением делает `Identify → Identify → AvatarRequest →
Avatar` и кладёт картинку в кэш в памяти. Целиком в датаграмму она не влезла бы,
а вложенная в представление пересылалась бы заново в каждом сообщении и в каждой
передаче файлов.

За отпечатком ходят ровно один раз: не получилось — значит буква. Повторы соблазнительны,
но объявления идут каждые четыре секунды, и любая схема «попробовать ещё» превращается
в шквал соединений на всю сеть. Пометка снимается вместе с уходом пира, так что
вернувшийся собеседник получает одну свежую попытку.

Присланные байты перехешируются и сверяются с запрошенным отпечатком, а сигнатура
проверяется на PNG или JPEG. Без первого пир отравил бы кэш, из которого картинку
берут все остальные с тем же отпечатком; без второго по сети приехал бы формат,
который декодирует не каждая платформа, — и у соседа картинка была бы пустым
прямоугольником без единой ошибки.

**Операционная система** едет рядом с отпечатком — и в объявлении, и в представлении.
Это одно слово, `windows`, `macos` или `android`, около двадцати байт, и в списке оно
становится иконкой рядом с аватаркой. По имени устройства не всегда видно, с чего
человек сидит, а это меняет ожидания: на Android нельзя отправить папку и не бывает
картинки учётной записи.

На проводе именно слово, а не перечисление, и это не мелочь. Незнакомое значение
перечисления `System.Text.Json` разворачивает в исключение, а разбор датаграммы
исключения гасит молча — собеседник на платформе, о которой эта сборка не знает,
пропал бы из списка целиком, не иконка, а сам пир. Слово же разбирается в «неизвестно»,
и строка остаётся на месте, просто без картинки. То же самое у старых сборок: поля
нет вовсе, и это ровно тот же «неизвестно».

**Присутствие видно в списке.** Собеседник в сети помечен зелёной точкой на аватарке.
Закрыл Чудика — строка не исчезает, а гаснет: точки нет, вместо адреса стоит
«не в сети», отправка запрещена, а прочитать и скопировать написанное раньше
по-прежнему можно. Ничего из этого не едет по сети: присутствие — это то самое
молчание дольше пятнадцати секунд, о котором сказано выше, просто раньше оно
выражалось одним лишь исчезновением строки.

Гаснет не всякий, а только тот, с кем есть переписка. Сосед, мелькнувший в списке
и ушедший, пропадает молча — иначе список за вечер зарастает теми, кому ни разу
не писали. Правило старое, ему просто не хватало вида: движок сообщает об уходе,
а показать это было нечем.

Вернувшийся занимает свою прежнюю строку вместе с перепиской. Идентификатор пира —
GUID процесса, поэтому после перезапуска собеседник формально другой, и без этого
в списке стояли бы две строки с одним именем: серая с разговором и живая пустая.
Узнаём по имени и системе и только среди погасших: живые не склеиваются никогда,
иначе два экземпляра на одной машине перестали бы быть двумя пирами, а на этом
держится весь цикл отладки. Безымянные не склеиваются тоже — «Без имени» одинаково
у всех, и по такому совпадению два разных телефона сошлись бы в одного собеседника
вместе с чужой перепиской.

**Приём файлов недоверенный по умолчанию.** Каждая принятая передача получает свежую
пустую папку; каждый путь из сети проходит проверку (`..`, абсолютные пути, UNC,
`CON`/`COM1`, хвостовые точки, bidi-подмена — всё отклоняется вместе со всей передачей);
файл пишется в `.part` и переименовывается только целиком. Недописанного файла,
выглядящего целым, не бывает.

**О программе — отдельный экран.** Знак вопроса в шапке открывает страницу с иконкой,
названием, версией, номером сборки, именем автора и адресом страницы релизов. До сих
пор узнать версию из самого приложения было негде: человек, поставивший APK или DMG,
не мог ни назвать её в жалобе, ни выяснить, где лежит свежая, — ссылка на релизы жила
только здесь, в README, до которого из приложения не дойти.

Версию экран спрашивает у системы, а не держит своей константой. Она уже задана
в csproj как `ApplicationDisplayVersion`, и второе место разошлось бы с первым в первый
же выпуск. Вдобавок сборочная автоматика дописывает к версии номер прогона — на своей
машине это «2.0», в выложенной сборке «2.0.42», — и константа показывала бы не то,
что человек скачал.

Адрес релизов стоит текстом кнопки, а не словами «Открыть страницу». Ровно так ссылка
выглядит в переписке: нажимаемым текстом и является сам адрес. И если открывать его
нечем — Launcher отказал, браузера нет, — адрес остаётся на экране, чтобы набрать
руками. Иконку страница берёт из того же файла, что и иконка приложения: синего
квадрата со скруглением в файле нет, его каждая система рисует сама, поэтому здесь
его рисует рамка вокруг картинки.

## Платформенные заметки

**Windows.** Сборка неупакованная. Это не только про удобство: внутри MSIX
AppContainer два экземпляра приложения не видят друг друга ни по loopback, ни по
адресу локальной сети — выглядит как ошибка протокола и ею не является. Для
упакованной сборки понадобится capability `privateNetworkClientServer`.
Брандмауэр спросит при первом запуске — разрешить «Частные сети».

Картинка учётной записи берётся из реестра:
`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AccountPicture\Users\{SID}` хранит
пути к готовым файлам разных размеров, из них выбирается ближайший к 192 пикселям.
Серый силуэт из `%ProgramData%` отвергается: он одинаков у всех на свете, то есть
менее содержателен, чем буква имени. Отсутствие ключа — норма, а не ошибка.

**Android.** Служба переднего плана типа `connectedDevice`, а не `dataSync`: у второго
с API 35 лимит шесть часов в сутки. `MulticastLock` обязателен — без него Wi-Fi-радио
отфильтровывает многоадресные кадры и телефон молча никого не видит. Принятое
складывается в папку приложения во внешнем хранилище: никаких разрешений, и всё
стирается при удалении приложения. Отправлять папки с Android нельзя — обход дерева
там требует SAF; файлы, в том числе несколько за раз, отправляются.

Звук на входящее играется напрямую через `RingtoneManager`, а не уведомлением:
канал `chudik-presence` создан с важностью `Low` и беззвучен по определению,
а важность канала Android после создания уже не меняет — на телефонах, где
приложение стоит давно, это не починить. Второй канал дал бы и вторую запись
в шторке, а нужен был звук.

Картинки учётной записи на Android нет и не будет. Публичного API для неё не
существует; ближайшее — фото владельца через `ContactsContract.Profile` — требует
`READ_CONTACTS`, то есть доступа ко всей адресной книге ради украшения. У собеседников
Android показывается буквой, а сам он картинки соседей видит как все.

Экранная клавиатура ужимает страницу, а не сдвигает окно. Умолчание MAUI —
`Pan`: окно уезжает вверх целиком, лишь бы показать поле ввода, и всё, что выше
поля, оказывается за верхним краем экрана. В пустом чате туда попадает первое же
отправленное сообщение — человек его не видит и думает, что не ушло. Поэтому
в `App` стоит `WindowSoftInputModeAdjust.Resize`, а корневая сетка `MainPage`
помечена `SafeAreaEdges="Default, Default, Default, All"`. Одного режима мало:
MAUI рисует край в край на всех версиях Android, штатный `adjustResize` там не
работает, и высоту под клавиатуру MAUI считает сама по оконным врезкам — но
только для той кромки, которая о клавиатуре знает.

Текст сообщения копируется долгим нажатием, а не из контекстного меню, как на
Windows и macOS. Меню тут просто нечем показать: обработчик `MenuFlyout` на
Android не зарегистрирован, а `MapContextFlyout` — пустой метод. Разметка меню
в пузырьке общая на все платформы и на Android ничего не делает, поэтому ветки
под платформу у неё нет; ветка есть у жеста — `TouchBehavior` включён только на
Android. На Windows это поведение помечает нажатие указателя обработанным и
захватывает его для любой кнопки, то есть съело бы правый клик вместе с меню,
а на macOS удержание левой кнопки копировало бы там, где принят правый клик.

Поведений на пузырьке два: одно на рамке, второе на самой подписи с текстом.
У сообщения со ссылкой появляются распознаватели жестов, и тогда нативный вид
подписи забирает касание себе — до рамки оно уже не доходит. С одним поведением
долгое нажатие работало бы на тексте сообщений без ссылок и молчало на тексте
сообщений с ними. У поведения на рамке вдобавок выключен
`ShouldMakeChildrenInputTransparent`: по умолчанию он проставляет детям рамки
`InputTransparent`, после чего ссылки перестают нажиматься совсем.

**macOS.** В `Info.plist` есть `NSLocalNetworkUsageDescription`: на macOS 15+ без него
запрос разрешения не показывается вовсе и всё локальное молча не работает. Entitlement
`com.apple.developer.networking.multicast` сознательно не добавлен — он выдаётся Apple
отдельно и без профиля ломает подпись. Если многоадресная рассылка на macOS не
заработает, остаются направленный broadcast, обход подсети и подключение по адресу.

Картинку учётной записи приходится спрашивать у `dscl`, отдельным процессом:
в биндингах Mac Catalyst нет OpenDirectory, а AppKit урезан до трёх десятков типов —
ни `CBIdentity`, ни `NSWorkspace` там нет. Атрибут `JPEGPhoto` вопреки имени часто
содержит TIFF, поэтому картинка пересобирается в PNG через `CGImageSource` — иначе
у собеседника на Android она была бы пустым прямоугольником. Если когда-нибудь
понадобится применить `Entitlements.plist` (например, ради Mac App Store), в песочнице
`Process.Start` запрещён и эта ветка умрёт целиком.

## Принятые решения

| Решение | Почему |
|---|---|
| Без шифрования | Домашняя сеть. Трафик виден любому в той же wifi — это осознанный размен |
| Только 1:1 | Общего канала нет |
| Ничего не сохраняем | Ни переписки, ни контактов, ни настроек. Только принятые файлы — их просили |
| Интерфейс на русском | Без инфраструктуры локализации |
| Картинка учётной записи — только на macOS и Windows | В Android публичного API нет, а `ContactsContract.Profile` требует `READ_CONTACTS` — доступ ко всей адресной книге ради украшения. Там остаётся буква |
| За картинкой ходим один раз на отпечаток | Объявления идут каждые четыре секунды. Повторы при неудаче — это шквал соединений на всю сеть ради украшения |
| Платформа едет словом, а не перечислением | Незнакомое значение перечисления рвёт разбор, а исключение в разборе датаграммы гасится молча. Пир на платформе из будущей сборки исчез бы у старых из списка целиком — не иконка, а сам пир |
| Свою платформу определяет ядро, а не голова | Имя устройства и картинку учётной записи добывают у системы, и без платформенного кода их не получить. Здесь же хватает `OperatingSystem`, а заодно правильное значение даром получает консольный стенд |
| Копируется сообщение целиком, а не выделенный кусок | На Mac Catalyst `UILabel` выделять не умеет вовсе: пришлось бы менять контрол и потерять размеченный текст, то есть нажимаемые ссылки. На Android выделение вдобавок ломает прокрутку списка и переиспользование ячеек |
| Ушедшему нельзя писать, но можно читать | Доставить некому: истории нет, сервера нет, сообщение просто пропало бы. Запертое поле ввода обещало бы, что скоро отпустят, поэтому вместо него надпись. Прочитать и скопировать написанное раньше человек вправе |
| Вернувшийся узнаётся по имени и системе | Идентификатор пира живёт ровно столько, сколько его процесс. Без этого правила перезапуск собеседника раздваивал бы его в списке: серая строка с перепиской и живая пустая |
| Безымянные не склеиваются | Имени у них нет, и зовутся все одинаково — «Без имени». Склеить человеку чужую переписку куда хуже, чем показать лишнюю строку |
| Строка ушедшего гаснет целиком, одной прозрачностью | В строке есть фотография, а у неё цвета нет — приглушает её только прозрачность. Красить подписи по отдельности значило бы завести два способа гасить одно и то же и следить, чтобы они не разошлись |
| Зелёный точки — не зелёный Android | Он уже стоит в этой же строке и означает систему. Вдобавок фирменный мятный даёт на светлой панели 1,7:1 — самый важный признак в списке оказался бы самым бледным пятном в нём |
| В сообщениях распознаются только `http` и `https` | Сообщение присылает кто угодно из сети, а нажатие на ссылку — это «открой тем, чем принято». `file:`, `ms-settings:` или чужая своя схема превратили бы пузырёк в кнопку запуска на вашей машине |
| Сценарий macOS не переподписывает бандл, а проверяет его | `dotnet publish` подписывает сам, ad-hoc и вместе с правами доступа. Проход `codesign --force --sign -` поверх этого права стирает: режима «сохранить, что было» у codesign нет. Без `allow-jit` среда исполнения .NET не стартует, и приложение умирает раньше dyld — значок прыгает, окна нет, отчёта о падении нет. Ровно так уехал образ 2.0.7. Права теперь проверяются поимённо: без этого поломка беззвучна, сборка зелёная, и узнаёт о ней только тот, кто скачал |
| В узком окне шапка говорит о собеседнике | Список за кадром, своей шапки у переписки нет, и своё имя над чужими сообщениями читается так, будто человек пишет сам себе. Вместе со списком уходят «Имя» и «Обновить»: обе про себя и про него, а рядом с чужим именем первая читается наоборот. Ценой этого в узкой переписке не видно строки состояния — она возвращается вместе со списком |
| «О программе» — страница, а не панель поверх главной | Маршрутов Shell в проекте не было, и это первый. Взамен возврат работает сам: аппаратная «Назад» на Android, жест возврата и стрелка в шапке. Панель поверх пришлось бы закрывать руками, а пропущенная аппаратная «Назад» на Android закрыла бы не панель, а всё приложение |
| Знак вопроса вместо слов «О программе» | В шапке рядом уже стоят «Имя» и «Обновить», и третья словесная кнопка на телефоне вытеснила бы обе. Ценой этого знак ни о чём не говорит, пока на него не нажали: подпись для чтения с экрана задана отдельно, но глазами её не видно |
| Иконка приложения объявлена ещё и картинкой | `MauiIcon` из разметки не адресуется — `Source=` видит только `MauiImage`. Копировать рисунок в третий файл (второй уже лежит в заставке) значило бы завести третье место, которое разъедется молча |

## Что проверено, а что нет

Проверено на Windows: обнаружение (в том числе двух экземпляров на одной машине),
переписка, передача файлов и деревьев, отмена, отказ, отклонение враждебных путей,
передача не блокирует чат, переход по ссылке из сообщения открывает браузер
по умолчанию.

Звук на входящее проверен по факту вызова: он происходит ровно на входящие
сообщения и не на свои, а пачка подряд даёт один звук, а не очередь звонков.
Звучание на слух — за человеком.

Проверено на Android: APK из релиза поставлен на телефон и работает.

Проверено на macOS: картинка учётной записи. Два экземпляра на одной машине нашли
друг друга, отпечаток доехал в объявлении, байты — отдельным соединением, и в шапке
и в списке собеседников видна настоящая фотография, а не буква. Заодно этим доказано,
что `Process.Start` под Mac Catalyst действительно форкает, `Environment.UserName`
отдаёт короткое имя, а `CGImageSource` разбирает TIFF из `JPEGPhoto`.

Копирование проверено на macOS против консольного стенда: правый клик по пузырьку
показывает «Копировать», в буфер уходит весь текст сообщения — в том числе у
сообщения со ссылкой, вместе с самой ссылкой и хвостом после неё, — в шапке
появляется «скопировал в буфер обмена», а нажатие на ссылку по-прежнему открывает
браузер. Последнее важнее всего: пузырёк обзавёлся и контекстным меню, и поведениями
касания, и сломать ссылки было проще всего именно здесь.

Копирование на Android не проверено вживую: на машине, где всё это писалось, нет
ни Android SDK, ни Java, и цель не собирается. Под сомнением там ровно одно — второе
поведение, то, что висит на подписи с текстом: сработает ли долгое нажатие поверх
сообщения со ссылкой. Если нет, оно снимается, и долгое нажатие остаётся на полях
пузырька и на строке со временем.

Копирование на Windows не проверено: машины под рукой не было. Контекстное меню там
строится один раз на ячейку, а не заново на каждый клик, как на macOS, — это
единственное место, где пути двух настольных систем расходятся.

Не проверено вживую на macOS: остальное. CI собирает образ на каждый коммит, но это
доказывает ровно одно — проект компилируется, подписывается и пакуется. Передачу
файлов на Маке по-прежнему нужно проверять руками.

Не проверена нигде ветка картинки учётной записи для Windows: путь в реестре взят
из документации, машины под рукой не было. Всё в ней падает в `null`, поэтому худшее,
что может случиться, — снова буква.

Проверено на macOS: иконка операционной системы. Приложение и консольный стенд нашли
друг друга, платформа доехала обоими каналами, и в списке у собеседника появилось
яблоко. Заодно измерено то, ради чего в `PeerPlatforms` стоит комментарий: под Mac
Catalyst `IsMacCatalyst()` возвращает true, `IsMacOS()` — **false**, а `IsIOS()` —
true. Проверяй мы одну `IsMacOS()`, собранное приложение объявляло бы себя
«неизвестным», хотя стенд на той же машине отвечал бы правильно.

Рядом со свежей сборкой в том же списке стояла сборка до этой правки — та, что
о платформе ничего не объявляет. Её строка выглядит ровно как прежде: колонка с
иконкой схлопывается в ноль, отступы не разъезжаются.

Иконки Windows и Android нарисованы, но вживую не показаны: ни Android SDK, ни
Windows-машины под рукой нет. Фигуры отрисованы отдельно и осмотрены в обеих темах,
а разметка у всех трёх одна и та же — отличаются только данные пути и цвет.
Перетаскивание реализовано только для Windows: штатный `DropGestureRecognizer` в MAUI
до сих пор падает на файлах из проводника, поэтому используется нативный обработчик,
и для Mac Catalyst такой же придётся написать отдельно.

Проверено на macOS: присутствие в списке. Приложение против консольного стенда,
все ветки по очереди. Стенд в сети — зелёная точка сидит на ободке аватарки,
рядом адрес. Стенд закрыт штатно, то есть с прощанием, — строка не исчезла,
а погасла: точки нет, строка приглушена целиком вместе с аватаркой и яблоком,
вместо адреса «не в сети», присланное раньше сообщение читается, а полоса ввода
сменилась надписью «Вера не в сети — сообщение не дойдёт».

Возвращение проверено отдельно, и это главное в правке. Перезапущенный стенд
объявился с другим идентификатором — `fc0dbf` вместо `8b8799`, — и всё же занял
ту же строку: она ожила, показала новый порт, переписка осталась на месте,
выделение не слетело, полоса ввода вернулась. Второй строки не появилось.

Склейка проверена и с обратной стороны. Два стенда с одним именем одновременно —
две отдельные живые строки, каждая со своей точкой и своим портом; не склейся
они, сломался бы основной приём отладки. Стенд, с которым переписки не было,
при выходе исчез из списка целиком, как и раньше.

Обе темы осмотрены. На светлой точка глубоко-зелёная в белом кольце, на тёмной
светлее и в кольце цвета панели; приглушённая строка читается в обеих, и слова
«не в сети» — тоже, ради чего им и поднят цвет.

Собиралось всё это с флагом `-p:ValidateXcodeVersion=false`: установленный Xcode 27
новее того, которого требует пакет .NET для Mac Catalyst (26.6), и штатная сборка
отказывает до всякой компиляции. К правке это отношения не имеет, но знать стоит —
без флага проект на такой машине не собрать вовсе.

Не проверено на Windows и Android: ни машины, ни SDK под рукой. Под сомнением там
ровно одно, и это Android: прозрачность на всю строку означает, что обрезанная
кругом картинка рисуется внутри слоя с альфой, а обрезка вместе с групповой
прозрачностью — исторически самое хрупкое сочетание на этой платформе. Выйдет
аватарка квадратом или с синим налётом — `Opacity` переезжает с корня строки
на три части содержимого, и заодно перестаёт глушить значок непрочитанных.
Там же не закрыт ещё один случай: если собеседник ушёл, пока человек набирал ему
сообщение, поле ввода исчезает из-под клавиатуры, а клавиатура остаётся.

Не проверен вживую и значок непрочитанных у погасшего собеседника: чтобы он
появился, нужно письмо от того, кто уже ушёл, а это та самая гонка, которая
ниже записана ограничением. Прозрачность перемножается, и цифра в значке
у погасшей строки заведомо бледнее обычного.

Проверено на macOS: шапка в узкой раскладке. Приложение против консольного стенда
и против второго своего экземпляра, окно 520 точек шириной. В переписке шапка
показывает собеседника: кружок с буквой у стенда, настоящая фотография у второго
экземпляра, имя и адрес под ним, «Имя» и «Обновить» убраны, «‹ Список» на месте.
Имя следит за собеседником вживую — переименование стенда доехало само, без
перевыбора, — а слишком длинное усекается хвостом и шапку не разрывает. Стенд
закрыт: адрес сменился на «не в сети» и посветлел, полоса ввода стала прежней
надписью с именем. Нажатие «‹ Список» возвращает шапку к себе — своя фотография,
своё имя, строка состояния и обе кнопки. Широкая раскладка осмотрена рядом
и осталась прежней.

Заодно закрыт случай, ради которого своя картинка и обёрнута отдельным блоком:
приложение запущено сразу узким, единственный собеседник выбрался сам, и своя
картинка учётной записи, которая приезжает уже после запуска, в шапке не всплыла —
там осталась чужая.

Проверено на macOS: экран «О программе». Приложение против второго своего экземпляра,
окно 520 точек шириной, тёмная тема. Знак вопроса стоит в шапке третьим, после «Имя»
и «Обновить», и открывает страницу: иконка нарисована белым Чудиком на синем квадрате
со скруглением — тем же рисунком, что и в доке, — под ней название, строка о том, что
это, «Версия 2.0» и «Сборка 1» ровно как в csproj, имя автора и адрес релизов. Нажатие
на адрес открывает страницу в браузере. Стрелка в шапке возвращает к списку, и шапка
Shell исчезает вместе со страницей — на главной её нет вовсе. В узкой раскладке
с открытой перепиской знак вопроса уходит вместе с «Имя» и «Обновить», а «‹ Список»
возвращает все три.

Не проверена светлая тема: цвета взяты теми же парами, что уже стоят на главной, но
глазами экран в ней не видели. Не проверено на Windows и Android: ни машины, ни SDK.
Отдельно не проверено главное, ради чего «О программе» сделана страницей, а не панелью
поверх главной, — что аппаратная «Назад» на Android возвращает к списку, а не закрывает
приложение. На Маке такой кнопки нет.

Проверено на macOS: образ 2.0.7 не запускался, причина найдена и закрыта. У бандла
из релиза права доступа оказались пустыми, у собранного локально — на месте. Причинность
проверена, а не выведена: тот же самый бинарник, переподписанный с правами, запускается —
шестнадцать библиотек и окно, — а без прав не тратит ни миллисекунды процессорного
времени и не загружает ни одной библиотеки. Сценарий переподпись больше не делает и
проверяет права поимённо; на сломанном бандле файл прав не создаётся вовсе, так что
проверка ловит именно этот случай. Сам сценарий целиком не прогонялся: pwsh на машине
нет, проверялись его команды `codesign` по отдельности — на рабочем бандле и на сломанном.

Отдельно всплыло: путь, по которому приложение однажды не запустилось, система
запоминает. Тот же исправленный бандл под именем `Тест.app` стартовал, а под прежним
`Чудик.app` — нет, причём и при прямом запуске бинарника, мимо LaunchServices;
`lsregister -u` этого не снимал, и переподпись на месте тоже. Снялось удалением
приложения и установкой заново: 2.0.8, положенный на тот же самый путь после того,
как сломанный оттуда убрали, запускается — двадцать две библиотеки и окно.
Перезагрузка, на которую здесь поначалу грешили, не понадобилась.

**Известное ограничение.** Вернувшийся узнаётся, только если мы уже заметили его
уход. Прощание — одна датаграмма без повторов, и когда его нет (процесс сняли,
пакет потерялся), уход замечает только таймаут в пятнадцать секунд. Перезапустись
собеседник быстрее — его новая строка встанет рядом со старой, ещё живой, склейка
её не возьмёт, и в списке окажутся две. Чинить это симметрично значит сливать две
переписки в одну, разбираясь с их порядком по времени; окно узкое, цена ошибки —
перемешанный разговор, и правильным показалось оставить как есть.
